| خاتىرىلەيدىغان ۋە قايتا قويىدىغىنى | ئورتاق كۇتۇپخانا قىلىپ تۈزۈلگەن ئەسلى نۇسخا، ctypes ئارقىلىق چاقىرىلىدۇ، ھەر بىر ئەھۋال ئۈچۈن بىر fork |

C دا توپ سىنىپلىرى يوق.

## يىمىرىلىش ۋە ئېنىقسىز ھەرىكەت

C فۇنكسىيەسىنىڭ كېلىشىمى سىرتىدىكى كىرگۈزۈشلەر (`isalpha(INT_MAX)`) segfault قىلىشى مۇمكىن. C قوزغاتقۇچى ھەر بىر ئەھۋالنى fork قىلىنغان بالا جەرياندا ئىجرا قىلىپ، `crash: SIGSEGV` نى خاتىرىلەيدۇ؛ `diff` بۇ يەردە كۆچۈرمىنىڭ ھەر قانداق ھەرىكىتىنى قوبۇل قىلىدۇ، چۈنكى C نىڭكى ئېنىقسىز. يىمىرىلمەيدىغان ئېنىقسىز ھەرىكەتنىڭ (`ispunct(1000)` glibc جەدۋىلىنىڭ سىرتىنى ئوقۇپ 1 قايتۇرىدۇ) تېخى ئىچكى بەلگىسى يوق: بۇنداق ئەھۋال `cases.jsonl` دىن قولدا ئۆچۈرۈلىدۇ.

## ئۇنى كۆچۈرۈش كېرەكمۇ؟

كۆپىنچە ياق، `analyze` قەيەردە ئىكەنلىكىنى ئېيتىدۇ. قاتتىق دېتال رېگىستىرلىرىغا تېگىدىغان، تەرجىمانىنىڭ تىپ چوڭلۇقى ياكى ئىچكى ساقلىغۇچ ئورۇنلاشتۇرۇشىغا تايىنىدىغان، ياكى قۇر ئىچى assembly ئىشلىتىدىغان (`volatile`، bitfield، packed struct، `__asm__`، ئادرېسقا ئايلاندۇرۇلغان پۈتۈن سانلار) C كودى "C دا قالسۇن" دەپ بەلگىلىنىدۇ: سىزنىڭ ماشىنىڭىزدىكى خاتىرە نىشان ھەققىدە ھېچنېمىنى ئىسپاتلىمايدۇ، مۇقىم قوزغاتقۇچ ياكى firmware كودى قايتا يېزىشتىن ئاز پايدا ئالىدۇ. ئۇنىڭ ئەتراپىدىكى كۆچمە لوگىكا (تەھلىل قىلىش، كېلىشىملەر، سانلىق مەلۇمات بىر تەرەپ قىلىش) ياخشى يۆتكىلىدۇ.

## چەكلىمىلەر

- **بۇففېر يەتكۈزىدىغان API لار.** C كۆۋرۈكى پەقەت سكالىر قىممەتلەر ۋە `const char *` نىلا يەتكۈزىدۇ. `char *out, size_t *outlen` ياكى ھالەت struct ى قوبۇل قىلىدىغان فۇنكسىيەلەر سەۋەبى بىلەن C دا قالىدۇ.
- **ماكرولار.** ماكرو ئارقىلىق ئېنىقلانغان فۇنكسىيەلەر تەھلىلچىنى خاتالىق دوكلات قىلدۇرىدۇ، پىلان ئۇ بىرلىكلەرنى قىسمەن دەپ بەلگىلەيدۇ.

## سۈرئەت

ھېچقانداق ئۆتۈش يوق: Rust كودى C كودى بىلەن بىۋاسىتە سېلىشتۇرۇلىدۇ. glibc facade دا `bench` ئومۇمىي ھېسابتا 0.87x نى ئۆلچىدى: ctype 1.1-1.4x تېز، glibc نىڭ ئەلالاشتۇرۇلغان `strtod`، `strspn`، `strcmp` لىرى 0.5-0.7x.
