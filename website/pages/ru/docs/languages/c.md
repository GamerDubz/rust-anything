# C

| | |
| --- | --- |
| Модуль | файл `.c` |
| Мост | функции `extern "C"` с исходными именами и заголовочный файл |
| Чем записывается и воспроизводится | оригинал, скомпилированный в разделяемую библиотеку, вызов через ctypes, отдельный fork на кейс |
| Требуется | компилятор C и Python 3.9+ (ctypes) |
| Статус | Проверен на glibc за фасадом: 1,859/1,859 после удаления одного кейса с неопределённым поведением, gate проходит |

Для C пакетные классы не генерируются.

## Падения и неопределённое поведение

Входные данные вне контракта функции C (`isalpha(INT_MAX)`) могут вызвать segfault. Драйвер C запускает каждый кейс в дочернем процессе через fork и записывает `crash: SIGSEGV`; `diff` принимает здесь любое поведение порта, поскольку поведение C не определено. Для неопределённого поведения, которое не приводит к падению (`ispunct(1000)` читает за пределами таблицы glibc и возвращает 1), встроенной метки пока нет: такой кейс удаляют из `cases.jsonl` вручную.

## Стоит ли его портировать?

Часто нет, и `analyze` подсказывает, где именно. Код на C, который работает с аппаратными регистрами, полагается на размеры типов или раскладку памяти конкретного компилятора или использует ассемблерные вставки (`volatile`, битовые поля, упакованные структуры, `__asm__`, целые числа, приводимые к адресам), помечается как «оставить на C»: запись на вашей машине ничего не доказывает о целевой платформе, а стабильный код драйверов или прошивок мало выигрывает от переписывания. Хорошо переносится переносимая логика вокруг него (парсинг, протоколы, обработка данных).

## Ограничения

- **API, передающие буферы.** Мост C передаёт только скаляры и `const char *`. Функции, принимающие `char *out, size_t *outlen` или структуру состояния, остаются на C, с указанием причины.
- **Макросы.** Функции, определённые через макросы, вызывают ошибки парсера, и план помечает такие модули как частичные.

## Скорость

Пересечения границы нет: код на Rust сравнивается с кодом на C напрямую. На фасаде glibc `bench` намерил 0.87x в целом: ctype быстрее в 1.1-1.4x, а оптимизированные в glibc `strtod`, `strspn`, `strcmp` дали 0.5-0.7x.
