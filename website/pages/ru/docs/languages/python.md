# Python

| | |
| --- | --- |
| Модуль | пакет или модуль |
| Мост | PyO3 (abi3), прямое преобразование, типизированные исключения |
| Чем записывается и воспроизводится | Python, импортирующий оригинал |
| Требуется | Python 3.9+ |
| Статус | Проверен на `colorsys.py` из CPython 3.13: 2,400/2,400, gate проходит |

Типы берутся из аннотаций типов. Нетипизированные параметры, используемые как числа (`r - g`, `max(r, g, b)`, `x < 1`), выводятся как числовые. `record --from-tests -- pytest` записывает каждый вызов, который делает собственный набор тестов оригинала (Проверено).

## Что порт должен сделать правильно

- Вызывающий код на Python передаёт `1` так же часто, как `1.0`, и целые числа проходят как есть. При записи целочисленные значения передаются как int в каждом четвёртом кейсе; порт с типом `f64` показал 134 расхождения, как только были записаны int. Используйте `crate::pynum::Num` для «int или float».
- `max(nan, 1, 2)` равно `nan`: побеждает первое значение, если только более позднее не окажется больше при сравнении.
- `-0.0 % 1.0` равно `0.0`.
- Ошибки, возвращённые как `Err("TypeName: message")`, становятся соответствующим исключением.

Код, уже скомпилированный numba, Cython или JAX, выполняется как машинный код: `profile` и `analyze` отмечают его, поскольку его портирование почти не даёт выигрыша в скорости.

## Скорость

Вызов в Rust стоит около 100-300 ns, а код на Rust гораздо быстрее интерпретатора, так что выигрывают даже маленькие функции. На `colorsys` `bench` намерил порт **в 1.35x быстрее** CPython на вызов (1.5-1.9x на большинстве вызовов). В виде пакета `slugify` на 20,000 строк ускорился с 98 ms до **в 17x быстрее** на 4 ядрах.
