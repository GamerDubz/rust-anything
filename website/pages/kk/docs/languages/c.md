C batch кластарын алмайды.

## Құлаулар және undefined behavior

C функциясының келісімшартынан тыс кірістер (`isalpha(INT_MAX)`) segfault тудыруы мүмкін. C драйвері әр кейсті fork жасалған еншілес процесте іске қосып, `crash: SIGSEGV` жазып алады; `diff` ол жерде порттың кез келген мінез-құлқын қабылдайды, өйткені C-дың мінез-құлқы анықталмаған. Құлатпайтын undefined behavior (`ispunct(1000)` glibc кестесінің шегінен тыс оқып, 1 қайтарады) үшін әзірге кірістірілген белгі жоқ: мұндай кейс `cases.jsonl` ішінен қолмен жойылады.

## Оны порттау керек пе?

Көбіне жоқ, және `analyze` қай жерде екенін айтады. Аппараттық регистрлерге қол тигізетін, компиляторының тип өлшемдеріне немесе жады орналасуына сүйенетін, не inline assembly қолданатын C коды (`volatile`, bitfield-тер, packed struct-тар, `__asm__`, адреске түрлендірілген бүтін сандар) "C-да қалдыру" деп белгіленеді: сіздің машинаңыздағы жазба target туралы ештеңе дәлелдемейді, ал тұрақты драйвер немесе firmware коды қайта жазудан аз ұтады. Оның айналасындағы тасымалданатын логика (парсинг, протоколдар, деректерді өңдеу) жақсы көшеді.

## Шектеулер

- **Буфер беретін API-лер.** C bridge тек скалярлар мен `const char *` тасымалдайды. `char *out, size_t *outlen` немесе күй struct-ын қабылдайтын функциялар себебі көрсетіліп, C-да қалады.
- **Макростар.** Макростар арқылы анықталған функциялар парсерді қате хабарлауға мәжбүр етеді, ал жоспар ол бірліктерді жартылай деп белгілейді.

## Жылдамдық

Шекарадан өту жоқ: Rust коды C кодымен тікелей салыстырылады. glibc facade-та `bench` жалпы 0.87x өлшеді: ctype 1.1-1.4x жылдамырақ, glibc-тің баптап оңтайландырылған `strtod`, `strspn`, `strcmp` функциялары 0.5-0.7x.
