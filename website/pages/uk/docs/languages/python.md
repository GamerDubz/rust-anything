# Python

| | |
| --- | --- |
| Модуль | пакет або модуль |
| Міст | PyO3 (abi3), пряме перетворення, типізовані винятки |
| Записує і відтворює | Python, що імпортує оригінал |
| Потрібно | Python 3.9+ |
| Статус | Перевірено на `colorsys.py` з CPython 3.13: 2,400/2,400, gate проходить |

Типи беруться з підказок типів. Нетипізовані параметри, що використовуються як числа (`r - g`, `max(r, g, b)`, `x < 1`), виводяться як числа. `record --from-tests -- pytest` записує кожен виклик, який робить власний набір тестів оригіналу (Tested).

## Що порт має зробити правильно

- Код на Python передає `1` так само часто, як `1.0`, і int проходять далі. Під час запису цілі значення передаються як int у кожному четвертому випадку; порт із типом `f64` показав 134 розбіжності, щойно int почали записуватися. Для int-або-float використовуйте `crate::pynum::Num`.
- `max(nan, 1, 2)` дорівнює `nan`: перше значення перемагає, якщо наступне не виявиться більшим при порівнянні.
- `-0.0 % 1.0` дорівнює `0.0`.
- Помилки, повернені як `Err("TypeName: message")`, стають відповідним винятком.

Код, уже скомпільований через numba, Cython чи JAX, виконується як машинний код: `profile` і `analyze` позначають його, бо його портування мало що дає у швидкості.

## Швидкість

Виклик у Rust коштує близько 100-300 ns, а код Rust набагато швидший за інтерпретатор, тож виграють навіть маленькі функції. На `colorsys` `bench` виміряв порт **у 1.35x швидше** за CPython на виклик (1.5-1.9x на більшості викликів). У пакеті `slugify` по 20,000 рядках перейшов з 98 ms до **у 17x швидше** на 4 ядрах.
