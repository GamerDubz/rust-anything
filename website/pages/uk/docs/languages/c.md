# C

| | |
| --- | --- |
| Модуль | файл `.c` |
| Міст | функції `extern "C"` з оригінальними іменами та заголовний файл |
| Записує і відтворює | оригінал, скомпільований у спільну бібліотеку і викликаний через ctypes, один fork на випадок |
| Потрібно | компілятор C і Python 3.9+ (ctypes) |
| Статус | Перевірено на glibc за фасадом: 1,859/1,859 після вилучення одного випадку з невизначеною поведінкою, gate проходить |

C не отримує пакетних класів.

## Збої та невизначена поведінка

Вхідні дані поза контрактом функції C (`isalpha(INT_MAX)`) можуть спричинити segfault. Драйвер C запускає кожен випадок у дочірньому процесі через fork і записує `crash: SIGSEGV`; `diff` приймає там будь-яку поведінку порту, бо поведінка C невизначена. Невизначена поведінка, яка не призводить до збою (`ispunct(1000)` читає за межами таблиці glibc і повертає 1), поки не має вбудованої позначки: такий випадок прибирають із `cases.jsonl` вручну.

## Чи варто його портувати?

Часто ні, і `analyze` каже, де саме. Код C, що працює з апаратними регістрами, покладається на розміри типів чи розміщення в пам'яті свого компілятора або використовує вбудований асемблер (`volatile`, бітові поля, упаковані структури, `__asm__`, цілі числа, приведені до адрес), позначається як "keep in C": запис на вашій машині нічого не доводить про цільову платформу, а стабільний код драйверів чи прошивки мало що виграє від переписування. Добре переноситься портабельна логіка навколо нього (розбір, протоколи, обробка даних).

## Обмеження

- **API, що передають буфери.** Міст C переносить лише скаляри і `const char *`. Функції, що приймають `char *out, size_t *outlen` або структуру стану, лишаються в C, із зазначеною причиною.
- **Макроси.** Функції, визначені через макроси, змушують парсер повідомляти про помилки, і план позначає такі модулі як часткові.

## Швидкість

Перетину межі немає: код Rust порівнюється з кодом C напряму. На фасаді glibc `bench` виміряв 0.87x загалом: ctype у 1.1-1.4x швидше, налаштовані в glibc `strtod`, `strspn`, `strcmp` 0.5-0.7x.
