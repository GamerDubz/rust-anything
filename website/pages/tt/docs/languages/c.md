C batch класслары алмый.

## Җимерелүләр һәм билгеләнмәгән тәртип

C функциясе контрактыннан читтәге кертмәләр (`isalpha(INT_MAX)`) segfault китерергә мөмкин. C драйверы һәр очракны fork ителгән бала процессында җибәрә һәм `crash: SIGSEGV` язып ала; `diff` анда портның теләсә нинди тәртибен кабул итә, чөнки C'ныкы билгеләнмәгән. Җимерелүгә китермәгән билгеләнмәгән тәртип (`ispunct(1000)` glibc таблицасыннан читтә укый һәм 1 кайтара) өчен әлегә эчке билге юк: андый очрак `cases.jsonl`'дан кулдан бетерелә.

## Аны күчерергәме?

Еш кына юк, һәм `analyze` кайда икәнен әйтә. Җиһаз регистрларына кагылучы, компиляторның тип зурлыкларына яки хәтер урнашуына таянучы яки inline assembly кулланучы C коды (`volatile`, bitfield'лар, packed структуралар, `__asm__`, адреска әйләндерелгән бөтен саннар) "keep in C" дип билгеләнә: сезнең машинадагы язма максат платформа турында бернәрсә дә исбатламый, ә тотрыклы драйвер яки firmware коды яңадан язудан аз отыш ала. Аның тирәсендәге күчмә логика (парсинг, протоколлар, мәгълүмат эшкәртү) яхшы күчә.

## Чикләр

- **Буфер тапшыручы API'лар.** C bridge бары скалярларны һәм `const char *` кына йөртә. `char *out, size_t *outlen` яки халәт структурасы кабул итүче функцияләр, сәбәбе күрсәтелеп, C'та кала.
- **Макрослар.** Макрослар аша билгеләнгән функцияләр парсерны хаталар турында хәбәр итәргә мәҗбүр итә, һәм план андый берәмлекләрне өлешчә дип билгели.

## Тизлек

Чик кичү юк: Rust коды C коды белән турыдан-туры чагыштырыла. glibc фасадында `bench` гомуми 0.87x үлчәде: ctype 1.1-1.4x тизрәк, glibc'ның көйләнгән `strtod`, `strspn`, `strcmp` функцияләре 0.5-0.7x.
