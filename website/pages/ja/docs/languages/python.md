# Python

| | |
| --- | --- |
| ユニット | パッケージまたはモジュール |
| ブリッジ | PyO3（abi3）、直接変換、型付き例外 |
| 記録とリプレイの実行方法 | Python で元のモジュールをインポート |
| 必要なもの | Python 3.9+ |
| ステータス | CPython 3.13 の `colorsys.py` で検証済み: 2,400/2,400、gate に合格 |

型は型ヒントから取得します。型のない引数で数値として使われているもの（`r - g`、`max(r, g, b)`、`x < 1`）は数値と推論されます。`record --from-tests -- pytest` は、元の実装自身のテストスイートが行うすべての呼び出しを記録します（Tested）。

## 移植版が正しく扱うべきこと

- Python の呼び出し元は `1.0` と同じくらい頻繁に `1` を渡し、int はそのまま受け渡されます。記録では 4 ケースに 1 回、整数値を int として渡します。`f64` で型付けした移植版は、int が記録されると 134 件の不一致を示しました。int または float には `crate::pynum::Num` を使ってください。
- `max(nan, 1, 2)` は `nan` です: 後の値の方が大きいと比較されない限り、最初の値が勝ちます。
- `-0.0 % 1.0` は `0.0` です。
- `Err("TypeName: message")` として返したエラーはその例外になります。

numba、Cython、JAX ですでにコンパイルされているコードはマシンコードとして実行されます: 移植しても速度はほとんど上がらないので、`profile` と `analyze` はそれを指摘します。

## 速度

Rust への呼び出しは約 100-300 ns で、Rust のコードはインタプリタよりはるかに速いので、小さな関数でも速くなります。`colorsys` では、`bench` の計測で移植版は呼び出しごとに CPython より **1.35 倍高速**でした（ほとんどの呼び出しで 1.5-1.9 倍）。バッチでは、20,000 文字列に対する `slugify` が 98 ms から 4 コアで **17 倍高速**になりました。
