# C

| | |
| --- | --- |
| ユニット | `.c` ファイル |
| ブリッジ | 元の名前を持つ `extern "C"` 関数とヘッダ |
| 記録とリプレイの実行方法 | 元のコードを共有ライブラリにコンパイルし、ctypes 経由でケースごとに fork して呼び出し |
| 必要なもの | C コンパイラと Python 3.9+（ctypes） |
| ステータス | ファサード経由の glibc で検証済み: 未定義動作のケースを 1 件除外して 1,859/1,859、gate に合格 |

C にはバッチクラスはありません。

## クラッシュと未定義動作

C 関数の契約外の入力（`isalpha(INT_MAX)`）はセグメンテーション違反を起こすことがあります。C のドライバーは各ケースを fork した子プロセスで実行し、`crash: SIGSEGV` と記録します。C の挙動は未定義なので、`diff` はそこでは移植版のどんな挙動も受け入れます。クラッシュしない未定義動作（`ispunct(1000)` は glibc のテーブルの範囲外を読んで 1 を返す）にはまだ組み込みのマーカーがありません: そうしたケースは `cases.jsonl` から手で削除します。

## 移植すべきか？

多くの場合はすべきではなく、`analyze` がそれがどこかを教えてくれます。ハードウェアレジスタに触れるコード、コンパイラの型サイズやメモリレイアウトに依存するコード、インラインアセンブリを使うコード（`volatile`、ビットフィールド、packed 構造体、`__asm__`、アドレスにキャストされる整数）は「C のまま残す」とマークされます: あなたのマシンでの記録はターゲット上のことを何も証明せず、安定したドライバーやファームウェアのコードは書き直しで得るものがほとんどありません。うまく移せるのは、その周りにあるポータブルなロジック（パース、プロトコル、データ処理）です。

## 制限

- **バッファを受け渡す API。** C ブリッジが扱うのはスカラーと `const char *` だけです。`char *out, size_t *outlen` や状態を持つ構造体を受け取る関数は、理由付きで C に残ります。
- **マクロ。** マクロで定義された関数があるとパーサーがエラーを報告し、計画はそのユニットを部分的（partial）とマークします。

## 速度

境界を越えるコストはありません: Rust のコードを C のコードと直接比較します。glibc のファサードでは、`bench` の計測値は全体で 0.87 倍でした: ctype は 1.1-1.4 倍高速、glibc のチューニング済み `strtod`、`strspn`、`strcmp` は 0.5-0.7 倍です。
