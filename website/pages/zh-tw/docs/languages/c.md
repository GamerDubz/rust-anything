# C

| | |
| --- | --- |
| 單元 | 一個 `.c` 檔案 |
| 橋接 | 使用原始名稱的 `extern "C"` 函式，以及標頭檔 |
| 錄製與重播方式 | 將原始程式編譯為共用函式庫，透過 ctypes 呼叫，每個案例一次 fork |
| 需求 | C 編譯器與 Python 3.9+（ctypes） |
| 狀態 | 已在外觀層後的 glibc 上驗證：移除一個未定義行為的案例後為 1,859/1,859，gate 通過 |

C 沒有批次類別。

## 當掉與未定義行為

超出 C 函式契約範圍的輸入（`isalpha(INT_MAX)`）可能造成 segfault。C 驅動程式會在 fork 出的子行程中執行每個案例，並錄製 `crash: SIGSEGV`；由於 C 在此的行為未定義，`diff` 會接受移植版本在這裡的任何行為。不會當掉的未定義行為（`ispunct(1000)` 會讀到 glibc 表格之外並回傳 1）目前還沒有內建標記：這類案例需要手動從 `cases.jsonl` 中移除。

## 你該移植它嗎？

通常不該，而 `analyze` 會告訴你哪些地方不該。會存取硬體暫存器、依賴編譯器的型別大小或記憶體配置，或使用行內組譯（`volatile`、位元欄位、packed struct、`__asm__`、整數轉型為位址）的 C 程式碼，會被標記為「留在 C」：在你的機器上錄製的內容無法證明目標平台上的任何事，而穩定的驅動程式或韌體程式碼也很少能從重寫中獲益。真正適合搬移的，是圍繞它們的可攜式邏輯（解析、通訊協定、資料處理）。

## 限制

- **傳遞緩衝區的 API。** C 橋接只能傳遞純量與 `const char *`。接收 `char *out, size_t *outlen` 或狀態結構的函式會留在 C 中，並附上原因。
- **巨集。** 透過巨集定義的函式會讓解析器回報錯誤，而計畫會將這些單元標記為部分可移植。

## 速度

沒有跨越成本：Rust 程式碼直接與 C 程式碼比較。在 glibc 外觀層上，`bench` 量測到整體為 0.87x：ctype 快 1.1-1.4x，glibc 調校過的 `strtod`、`strspn`、`strcmp` 為 0.5-0.7x。
