C batch класстарын албайт.

## Кулоолор жана аныкталбаган жүрүм-турум

C функциясынын келишиминен тышкары киргизүүлөр (`isalpha(INT_MAX)`) segfault бериши мүмкүн. C драйвери ар бир кейсти fork кылынган бала процессте иштетет жана `crash: SIGSEGV` деп жазат; `diff` ал жерде порттун каалаган жүрүм-турумун кабыл алат, анткени C'нын жүрүм-туруму аныкталбаган. Кулатпаган аныкталбаган жүрүм-турум (`ispunct(1000)` glibc таблицасынан ары окуп, 1 кайтарат) үчүн азырынча орнотулган белги жок: мындай кейс `cases.jsonl`'дан кол менен алынып салынат.

## Аны порттоо керекпи?

Көп учурда жок, жана `analyze` кайсы жерде экенин айтат. Жабдыктын регистрлерине тийген, компилятордун тип өлчөмдөрүнө же эс тутумдагы жайгашууга таянган же inline assembly колдонгон C коду (`volatile`, bitfield'дер, packed struct'тар, `__asm__`, даректерге айландырылган бүтүн сандар) "C'да калтыруу" деп белгиленет: сиздин машинаңыздагы жазуу максаттуу платформа жөнүндө эч нерсени далилдебейт, ал эми туруктуу драйвер же firmware коду кайра жазуудан аз пайда алат. Анын айланасындагы көчүрүлмө логика (талдоо, протоколдор, маалымат менен иштөө) жакшы көчөт.

## Чектөөлөр

- **Буферлерди берген API'лер.** C bridge'и скалярларды жана `const char *` гана өткөрөт. `char *out, size_t *outlen` же абал struct'ун кабыл алган функциялар себеби көрсөтүлүп, C'да калат.
- **Макростор.** Макростор аркылуу аныкталган функциялар парсерге ката бергизет, жана план ал бирдиктерди жарым-жартылай деп белгилейт.

## Ылдамдык

Чектен өтүү жок: Rust коду C коду менен түз салыштырылат. glibc facade'ында `bench` жалпысынан 0.87x өлчөдү: ctype 1.1-1.4x ылдамыраак, glibc'тин тюнингделген `strtod`, `strspn`, `strcmp` 0.5-0.7x.
