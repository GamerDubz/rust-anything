# Python

| | |
| --- | --- |
| 유닛 | 패키지 또는 모듈 |
| 브리지 | PyO3 (abi3), 직접 변환, 타입이 있는 예외 |
| 기록과 재생 담당 | 원본을 import하는 Python |
| 필요 조건 | Python 3.9+ |
| 상태 | CPython 3.13의 `colorsys.py`에서 검증: 2,400/2,400, 게이트 통과 |

타입은 타입 힌트에서 가져옵니다. 타입이 없지만 숫자로 쓰이는 매개변수(`r - g`, `max(r, g, b)`, `x < 1`)는 숫자로 추론합니다. `record --from-tests -- pytest`는 원본의 자체 테스트 스위트가 하는 모든 호출을 기록합니다(Tested).

## 포트가 정확히 맞춰야 할 부분

- Python 호출자는 `1.0`만큼 `1`도 자주 넘기며, int는 그대로 전달됩니다. 기록은 네 번째 케이스마다 정수 값을 int로 넘깁니다. `f64`로 타입을 지정한 포트는 int가 기록되자 134개 불일치를 보였습니다. int-or-float에는 `crate::pynum::Num`을 사용하세요.
- `max(nan, 1, 2)`는 `nan`입니다. 이후 값이 더 크다고 비교되지 않는 한 첫 번째 값이 이깁니다.
- `-0.0 % 1.0`은 `0.0`입니다.
- `Err("TypeName: message")`로 반환한 오류는 해당 예외가 됩니다.

numba, Cython, JAX로 이미 컴파일된 코드는 기계어로 실행됩니다. 포팅해도 속도 이득이 적으므로 `profile`과 `analyze`가 이를 표시합니다.

## 속도

Rust 호출 비용은 약 100-300 ns이고 Rust 코드는 인터프리터보다 훨씬 빠르므로, 작은 함수도 이득을 봅니다. `colorsys`에서 `bench`는 포트가 호출당 CPython보다 **1.35배 빠르다**고 측정했습니다(대부분의 호출에서 1.5-1.9x). 배치로 하면 문자열 20,000개에 대한 `slugify`가 98 ms에서 4코어 기준 **17배 빨라졌습니다**.
