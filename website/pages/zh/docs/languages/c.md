# C

| | |
| --- | --- |
| 单元 | 一个 `.c` 文件 |
| 桥接层 | 与原函数同名的 `extern "C"` 函数及头文件 |
| 录制与回放方式 | 将原实现编译为共享库，通过 ctypes 调用，每条用例一个 fork |
| 依赖 | C 编译器和 Python 3.9+（ctypes） |
| 状态 | 已在门面后的 glibc 上验证：去掉一条未定义行为用例后 1,859/1,859，门禁通过 |

C 不支持批处理类。

## 崩溃与未定义行为

超出 C 函数约定范围的输入（`isalpha(INT_MAX)`）可能导致段错误。C 驱动会在 fork 出的子进程中运行每条用例，并记录 `crash: SIGSEGV`；对这类用例，`diff` 接受移植版的任何行为，因为 C 的行为本身就是未定义的。不会导致崩溃的未定义行为（`ispunct(1000)` 越过 glibc 的表读取并返回 1）目前还没有内置标记：这类用例需要手动从 `cases.jsonl` 中删除。

## 应该迁移它吗？

通常不该，`analyze` 会告诉你具体位置。操作硬件寄存器、依赖编译器的类型大小或内存布局、或使用内联汇编的 C 代码（`volatile`、位域、紧凑结构体、`__asm__`、整数强转为地址）会被标记为“保留在 C 中”：在你的机器上录制的结果证明不了目标平台上的任何行为，而且稳定的驱动或固件代码从重写中获益很少。真正适合迁走的是它周围的可移植逻辑（解析、协议、数据处理）。

## 限制

- **传递缓冲区的 API。** C 桥接层只支持标量和 `const char *`。接收 `char *out, size_t *outlen` 或状态结构体的函数会保留在 C 中，并注明原因。
- **宏。** 通过宏定义的函数会让解析器报错，规划会把这些单元标为部分迁移。

## 速度

这里没有跨边界开销：Rust 代码直接与 C 代码对比。在 glibc 门面上，`bench` 测得整体为 0.87x：ctype 快 1.1-1.4 倍，而 glibc 精心调优的 `strtod`、`strspn`、`strcmp` 为 0.5-0.7x。
