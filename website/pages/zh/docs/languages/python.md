# Python

| | |
| --- | --- |
| 单元 | 包或模块 |
| 桥接层 | PyO3（abi3），直接类型转换，类型化异常 |
| 录制与回放方式 | Python，导入原实现 |
| 依赖 | Python 3.9+ |
| 状态 | 已在 CPython 3.13 的 `colorsys.py` 上验证：2,400/2,400，门禁通过 |

类型来自类型注解。未标注类型但按数值使用的参数（`r - g`、`max(r, g, b)`、`x < 1`）会被推断为数值。`record --from-tests -- pytest` 会录制原实现自身测试套件发出的每一次调用（已测试）。

## 移植版必须做对的地方

- Python 调用方传 `1` 和传 `1.0` 一样常见，整数会原样传入。录制时每四条用例中就有一条把整数值作为 int 传入；一个类型为 `f64` 的移植版在录制了 int 之后出现了 134 处不一致。需要“整数或浮点数”时请使用 `crate::pynum::Num`。
- `max(nan, 1, 2)` 是 `nan`：除非后面的值比较结果更大，否则第一个值胜出。
- `-0.0 % 1.0` 是 `0.0`。
- 以 `Err("TypeName: message")` 返回的错误会变成对应的异常。

已经由 numba、Cython 或 JAX 编译为机器码的代码：`profile` 和 `analyze` 会把它标出来，因为迁移它几乎换不来速度提升。

## 速度

调用 Rust 的开销约为 100-300 ns，而 Rust 代码比解释器快得多，所以即使是小函数也能获益。在 `colorsys` 上，`bench` 测得移植版逐次调用比 CPython **快 1.35 倍**（大多数调用为 1.5-1.9x）。改成批处理后，`slugify` 处理 20,000 个字符串，从 98 ms 变为在 4 核上**快 17 倍**。
